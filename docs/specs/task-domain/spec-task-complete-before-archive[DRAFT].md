## 0. 新会话接手须知

1. 现状：`IsCompleted == true` ⇔ 活动查询排除 ⇔ 侧边栏「已完成归档」展示。勾选后 `LoadTasksAsync` 立即消失。
2. 目标：`IsCompleted` 只表示勾选完成；**进入「已完成归档」视图**需要单独的归档动作。
3. Article 9：若曾考虑 `Task.Delay` 自动归档 —— **已否定**；禁止用墙钟定时作为归档触发。

---

## 1. Why

用户两次指向同一根因：完成操作与离开当前列表绑定过紧，误触只能去归档里找。

Attribution：`Design Wrong` —— 将「完成」与「归档」做成同一状态。

---

## 2. What

### 2.1 领域契约变更

在 `TaskItem`（或等价模型）增加归档维度，例如：

| 字段 | 语义 |
| :--- | :--- |
| `IsCompleted` / `CompletedAt` | 用户勾选完成；可再次取消勾选清除 |
| `IsArchived` / `ArchivedAt`（新） | 已进入归档堆；**仅**由显式归档动作置位 |

**不变量（草案）**：

1. `IsArchived == true` 之前必须 `IsCompleted == true`（未完成不可归档）—— **[待裁决 D1]** 是否允许例外。
2. 取消勾选：若尚未归档 → `IsCompleted=false`，`CompletedAt=null`，仍在原列表。
3. **[待裁决 D2]** 已归档后是否允许直接取消勾选拉回，或必须「取消归档」。

### 2.2 查询语义

| 视图 | 过滤 |
| :--- | :--- |
| 全部 / 项目活动列表 | `!IsDeleted && !IsArchived`（**含**已完成未归档） |
| 已完成归档 | `!IsDeleted && IsArchived` |
| 小窗单项目列表 | 同活动列表 + `ProjectId` |

### 2.3 UI

- 已完成未归档：沿用现有归档行的**划线 + 低饱和**样式，但留在当前列表。
- 取消勾选即可恢复（容错）。
- **归档触发（用户裁决 2026-09-16）**：手动；将**该项目下已完成**任务列入归档，**保留 `ProjectId` 来源**（不是「整棵项目归档消失」）。控件位置仍 [待裁决 D3]。

### 2.4 待裁决

| # | 议题 | 候选 |
| :--- | :--- | :--- |
| D1 | 未完成能否归档 | A 不能（推荐） / B 能 |
| D2 | 已归档回退 | A 归档视图内取消归档 / B 允许直接取消完成并出归档 |
| D3 | 手动归档入口 | A 侧边栏「归档已完成」/ B 项目上下文菜单 / C 多选批量 / D 以上组合 |
| D4 | 历史数据 | 已有 `IsCompleted=true` 的行：A 视为已归档（一次迁移） / B 视为已完成未归档（突然挤回活动列表） |

**[推断] D4 推荐 A**：避免升级后活动列表被历史完成项淹没。须用户确认。

### 2.5 非本 SPEC

- 通用撤销/重做栈
- 定时自动归档
- 小窗列表布局（仅消费本语义）

## 3. How（确认前不执行）

1. 修订 REQUIREMENTS（完成≠归档、手动归档）；修订 design §7.3 去掉「仅延长动画」推断，写入本契约；修订 domain 字段表。
2. 模型 + 仓储查询/迁移（sqlite-net `CreateTable` 加列）；按 D4 迁移脚本或启动校正。
3. `ToggleCompleteAsync`：不再依赖「完成即离开活动列表」。
4. 新增 `ArchiveCompleted*` API 与 UI 入口（D3）。
5. 样式：活动列表中完成态复用 `.Completed`。
6. 单测：完成保留、取消勾选、归档迁移、视图过滤。
7. 构建 + 测试；人工验误触回退。
